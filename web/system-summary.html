02 · Deterministic pipeline

每次刷新经过七个确定性步骤

01 获取RSS、Atom、JSON、HTML；并发、超时、单源隔离
02 归一标题、摘要、时区、URL、语言和稳定 ID
03 去重同站重复与旧闻隔离，未来时间钳制
04 聚类Jaccard、SimHash、跨语实体/金额和冲突约束
05 证据owner 与角色去重，声明、报道、线索分层
06 关联公司、证券、政策、市场资产与证据片段
07 输出排序、搜索、AI 雷达、监控、简报和 API
规则可信度 = 40% × 来源权威 + 30% × 独立印证 + 20% × 文本质量 + 10% × 时间一致性
最终排序 = (55% × 可信度 + 45% × 相关性) × 时效衰减

这些步骤全部可解释、可测试，不依赖大模型。大模型不可用、超时或关闭时，数据库、聚类、搜索和告警都不会中断。

03 · LLM layer

大模型在其中怎么工作

LLM 位于规则聚类之后，而不是抓取之前。它只读取排名靠前的事件包：主标题、来源数、独立集团数、最高来源等级、最多 8 个来源标题和有限摘要。它看不到管理令牌，也不负责访问原网页。

候选选择按规则 rank 选择 Top N；已有同模型同 prompt 版本结果则跳过
上下文封装标题、来源结构、摘要；限制长度降低成本和注入面
结构化判断temperature 0.2，强制 JSON 输出
内容指标事实密度、夸张度、决策相关性
解释产物摘要、so what、claims、red flags、核查建议
规则融合LLM 对可信度最多占 25%，规则始终占 75%
持久化记录模型与 prompt 版本，结果可缓存、可审计
LLM 输出用途明确不能代表
factuality文本中可核查主体、数字、时间和出处的密度事件发生概率或“真假分”
sensationalism标题是否相对正文夸张对媒体立场的政治判断
relevance对投资、职业和重大决策的价值适合所有用户的普遍价值
claims把文本整理为待核查断言断言已经得到外部证实
red_flags提示无出处、因果跳跃、软广、数据缺口径等自动判定造假
verify_next给出下一步核查方向替用户完成最终尽调
当前运行状态：关闭。服务器没有配置 DASHSCOPE_API_KEY，Supervisor 也未带 --llm 启动。当前页面中的证据分、聚类和 AI 雷达全部来自规则与来源数据，不是模型“编出来”的。
04 · On versus off

打开与关闭，大体有什么区别

LLM OFF · 当前生产状态

稳定、便宜、完全可复现

  • 抓取、去重、聚类、证据链全部运行
  • FTS、资产检索、AI 雷达、监控和简报全部运行
  • 无模型费用、无模型数据外发、结果完全确定
  • 只有规则摘要；难理解隐含因果、软广和复杂语义
  • 不同措辞但语义相同的事件召回仍有限
LLM ON · 可选增强

更会读，但不取代证据

  • 增加一句话摘要、行动意义和待核查 claims
  • 识别标题夸张、因果跳跃、口径缺失与软广
  • 改善个人相关性排序和阅读效率
  • 需要 API Key，会产生延迟、调用成本和数据外发
  • 可能幻觉；因此不能创建来源、不能把孤证升级成多源事实

05 · Guardrails

如何避免模型成为“真相机器”

程序硬约束

  • 模型不决定来源层级、owner 或独立集团数。
  • 模型无法增加“多源印证”数量。
  • 融合权重封顶 25%，red flag 只会扣分。
  • 过滤“超出知识截止日期所以可疑”等错误判断。
  • 严格 JSON 校验；单条失败不阻断流水线。
  • 缓存键包含模型名和 prompt 版本，升级可追踪。

仍需补强

  • Prompt injection 与恶意正文的专项红队集。
  • 不同模型之间的一致性和漂移监控。
  • claims 到原文精确段落的逐句引用。
  • 真实人工评审集，而非只依赖模板化测试。
  • 敏感来源送模前的字段级脱敏策略。
设计底线：来源事实与模型判断分栏保存。任何没有原始链接和证据片段的模型输出，只能作为阅读提示，不能显示为“已证实”。
